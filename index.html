Engineering Challenges

1. Production State Management Crashes

MobX-State-Tree occasionally produced protected object mutation errors during asynchronous updates.

I restructured store actions, ensured mutations occurred only inside model actions, and wrapped affected screens with observers where necessary.

The production crash was eliminated.

2. VirtualizedList Failures

Some chat and feed screens experienced runtime crashes caused by invalid list items.

I introduced defensive runtime validation and safer list rendering strategies, preventing crashes without affecting user experience.

3. Framework Upgrade

Migrating the application to newer Expo SDK versions together with React 19 required careful dependency updates.

Authentication, push notifications, image pickers, and native plugins were all validated across release builds to ensure compatibility.

4. Image Processing Issues

Some uploaded profile photos appeared stretched or incorrectly compressed.

I investigated the image processing pipeline, corrected aspect-ratio handling, and added upload state management to provide better user feedback.

5. Push Notification Navigation

Opening a notification needed to navigate directly into the correct chat thread while preserving navigation history.

I implemented deep-link navigation logic that maintained a consistent back-stack, resulting in a much smoother user experience.

Feedback from Amitoj Singh

Overview

Sarab Rog Ka Aukhad Nam (SRKAN) Mission Trust is a Sikh spiritual and charitable trust based in Ludhiana, India. The name translates to "The Divine Name is the medicine for all ills." The trust serves a global, multilingual community of devotees through prayer, spiritual programs (Samagams), healing journeys, and seva.

The mission ran almost entirely offline — schedules lived in print, content had no home, and there was no mobile presence at all. I was brought in to build a full-stack digital ecosystem: one API powering a public donation website, a staff admin dashboard, and a native mobile app.

This case study focuses on the mobile app — the surface most devotees live in — and the engineering behind making the mission work in their pocket, in their language, even offline.

Project Information

RoleFull-Stack Developer (Product Owner of the build)
FocusMobile app — iOS & Android (React Native / Expo)
EcosystemPublic website · Admin dashboard · Mobile app · REST API
Mobile StackExpo SDK 55 / React Native, Redux Toolkit, TanStack Query, SQLite, expo-notifications, expo-av, i18n, dark/light themes

The App

A five-tab native app used daily by devotees worldwide — many of them older, many of them in the diaspora. The core experience has to work without connectivity, in three languages, with audio that keeps playing in the background and reminders that fire at the right local moment.

  • Home — today's Samagams front and center, healing journeys, and the trust's latest content
  • Shabad Jaap — scripture reader with audio for chanting along, cached in SQLite for offline use
  • Programs — Samagams & daily session schedules, timezone-aware per branch
  • Media — curated YouTube recordings of broadcasts and kirtan
  • Settings — language (English / Punjabi / Hindi), dark / light theme, notification controls

The Business Problem

SRKAN had a global community but no digital presence to serve it. For the mobile surface, concretely:

  • No mobile experience. Devotees — including an older demographic and a large diaspora — had no way to reach the mission from their phone
  • Fragmented program information. Daily sessions and Samagams lived in print and were not discoverable
  • No content channel. Live broadcasts, recorded media, and healing-journey content had no home
  • Language and connectivity barriers. Devotees needed the app in English, Punjabi, or Hindi — and needed scripture to work without an internet connection

Why Mobile Was Difficult

1. The iOS 60-notification cap

iOS limits apps to 60 scheduled local notifications at a time. With recurring samagams and daily session reminders across multiple branches, I had to design a bounded scheduling plan — upcoming programs first, then daily-session reminders — that never exceeded the cap and still reminded devotees at the right local moment.

2. Audio that survives the background

A live-radio stream and audio-based Shabad Jaap had to keep playing when the app went to background or the screen locked. I wired up audio mode / background playback configuration so kirtan doesn't drop the moment a devotee switches apps.

3. Offline scripture

Shabad Jaap had to work in places with no signal. The full scripture dataset is cached locally in SQLite so chanting works offline — while schedule and media data stay fresh from the API.

4. Three languages, including Gurmukhi

The entire UI — tabs, labels, notifications, scripture — is translated into English, Punjabi (Gurmukhi script), and Hindi, with a language switch that applies instantly across the app.

5. Timezones and scheduling

Branches are in different regions and samagams recur. Program start times must render correctly for each user and drive notifications that fire at the right local moment.

6. One app, many devices

A single React Native codebase ships to both iOS and Android via Expo, with the themed dark/light UI, audio, notifications, and SQLite all behaving consistently on both platforms.

Mobile Architecture

One API, thin clients

A single Node backend owns all data; the app is a client of the same API as the website and admin panel. No duplicated business logic, no drift. A schedule edited in the admin panel appears in the app that evening, in the correct timezone, for the correct branch.

Redux Toolkit + React Query

Redux Toolkit holds global UI and player state — the floating audio player, theme, language, notification prefs. TanStack Query handles server state: fetching, caching, and refreshing schedules, samagams, and media from the API.

SQLite for offline scripture

Scripture is bundled and cached locally in SQLite for offline chanting. Schedule and media data stay fresh from the API — the core experience keeps working without connectivity, the dynamic content stays current.

Local notifications, bounded

Reminders are scheduled locally (no push infrastructure), using a bounded plan that fits the iOS 60-notification cap: upcoming programs first, then daily-session reminders.

Key Trade-Offs

  • Local scheduled notifications vs. a push-notification service. Local notifications avoided standing up push infrastructure and worked reliably across the diaspora — at the cost of the iOS 60-notification cap, managed with a bounded scheduling plan.
  • SQLite offline cache vs. always-online. Scripture data is cached locally for offline chanting; schedule and media data stay fresh from the API.
  • Streaming pivot. Full video streaming was narrowed to curated YouTube recordings — far more reliable than self-hosted streaming for the trust's bandwidth and audience.
  • Single codebase, two stores. One React Native / Expo app ships to iOS and Android — a shared codebase instead of two native apps.

Impact

  • A real mobile presence for the mission. Devotees worldwide get today's samagams, live radio, media, healing journeys, and Shabad Jaap — in English, Punjabi, or Hindi — with reminders that fire at the right local time.
  • Works offline, in three languages. Scripture is available without connectivity, and the whole app speaks the devotee's language including Gurmukhi script.
  • One source of truth, three channels. A schedule, program, or streaming link updated once in the admin panel is instantly consistent across the website and mobile app.
  • Audio that follows you. Live radio and Shabad Jaap keep playing in the background — built for daily use, not occasional browsing.

What I'd Do Differently

  • Push notification infrastructure becomes worth it if the community grows large enough to hit the local-notification cap — a natural next investment
  • Add observability earlier. Structured logging and error tracking from day one would have made background-audio and notification edge cases easier to debug
  • Automated end-to-end coverage on mobile. More device-matrix testing across iOS and Android releases

Final Thoughts

The SRKAN app is a companion, not a brochure. The hardest problems were the ones a spec doesn't surface — the iOS notification cap, audio in the background, offline scripture, three languages including Gurmukhi, and timezones for a global diaspora. Solving those is what turned a website project into a mission that lives in devotees' pockets.
