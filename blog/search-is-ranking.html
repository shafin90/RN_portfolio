Search is ranking, not a text box

The moment a catalog is real, “a search bar” becomes a ranking problem, a script problem, and a network problem. The UI is the least of it.

Users do not experience your schema. They experience whether typing still returns something useful on a bad radio. If the query scans the table, the spinner is the product. If the fields are wrong, empty is the product. If the script is Gurmukhi and you only indexed Latin, you have built a wall and called it discovery.

The patterns that held up for me were unglamorous. Multi-criteria matching that still felt instant. Geocode first, then filter, so people are not typing a place the database never stored. Geo-indexed “near me + skill” so a demo does not die the first time the dataset is honest.

The contract I keep is small: type, get a result, keep typing. No spinner tax as the catalog grows. That is not a frontend trick. It is indexes, query shape, and the humility to put ranking in the system instead of in a list you sorted in memory because the first ten rows looked fine.

Founders feel search as conversion. Engineering should feel it as a budget: latency, relevance, scripts, and the index you will actually maintain. Everything else is decoration on a text box.
